# Astra structured output compatibility

`InferenceServiceProvider` registers an OpenAI provider through Prism's public manager extension during registration, before cassette boot wraps providers. Exact `gpt-6-astra` requests use the native Responses transport, schema format, refusal handling, usage decoding, retry configuration and per-call credentials. Other models and modalities delegate to Prism unchanged; invented future aliases retain upstream refusal. For Astra, transport format names already matching OpenAI’s 1–64 character ASCII letter/digit/underscore/hyphen rule remain unchanged. Other schema names (including the domain identity `music/intent`) receive a deterministic `schema_` plus SHA-256-derived label. The schema body and domain identity remain unchanged; this label only satisfies the provider transport contract. No model fallback or music-specific inference API is introduced.

Prism 0.100.1 and its upstream main resolver omit Astra from a hard-coded structured-mode list. [OpenAI's model contract](https://developers.openai.com/api/docs/models/gpt-6-astra), checked 2026-09-09, explicitly supports structured outputs. The compatibility handler only supplies that missing admission and the same schema envelope; it does not claim audio understanding or provider access. Remove these compatibility subclasses when the supported Prism floor includes the alias, retaining the transport regression tests.

The public HTTP-boundary tests cover explicit and auto structured mode, exact model/schema/strictness, per-call credentials, native response/usage decoding, a previously supported model, and unknown-model refusal before transport. Credentials in tests are synthetic. They establish request behavior, not account entitlement or music quality.
